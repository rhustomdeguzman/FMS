RFP attachment import deployment
===============================

1. Run `FineReportAttachmentImportMigration.sql` against FMS. The migration uses `New_ORFP_Hdr.Attachment_Folder`.
2. Publish the updated API to `D:\API\FMS_API` and restart its IIS application. The existing SQL Agent request import job stays unchanged.
3. Give the API application pool identity read access to `D:\xampp\htdocs\NewORFPv3\public\Request For Payment` and modify access to `D:\API\FMS_API\Uploads`. These are paths on the API server. For a source on another server, configure an accessible UNC share instead.

While the API is running, its worker checks on startup and every 30 seconds. It matches imported requests (`RequestNumber = RFP-<RF_Number>`) to `New_ORFP_Hdr`, joins `Attachment_Folder` to `temporary_files.folder`, and reads `temporary_files.filename`. Existing imported requests are backfilled too; outbound RFPs generated by FMS are excluded.

Source files are copied directly from the source directory into `Uploads\liquidation\<CashAdvanceRequestId>\rfp-import-<ImportId>.<extension>`. The upload root is under the API content root; publishing to `D:\API\FMS_API` gives the requested destination. FMS shows the original filename from attachment metadata.

Only completed copies are registered in `FMS_CashAdvanceAttachments`. Import tracking prevents duplicate registration. Missing/inaccessible files are logged and retried. A complete copy survives database failures for registration on retry. Source files are preserved. Changing a source file under the same name does not replace its imported snapshot.

Optional configuration (merge into deployed appsettings):

```json
"RfpAttachmentImport": {
  "Enabled": true,
  "SourceRoot": "D:\\xampp\\htdocs\\NewORFPv3\\public\\Request For Payment"
}
```

Keep the IIS API application running for imports without user traffic. Pending copies resume when an idle/stopped API starts again.

After deployment, import an eligible RFP with a file, allow a worker cycle, refresh FMS, and download its attachment. Check `FMS_RfpAttachmentImports.AttachmentId` and API logs for missing copies. Live SQL mapping and server folder access require server verification; local checks cover file copying only.
